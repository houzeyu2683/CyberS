## 任務一：`kits/threat.py` 新增 `check_epss`

### API
```
GET https://api.first.org/data/v1/epss?cve={cve_id}
```
完全公開免費，不需要任何 token。

### 回傳格式
```python
{"epss_score": 0.97565, "epss_percentile": 0.99984}
```
- `epss_score`：被利用的機率（0～1）
- `epss_percentile`：相對於所有 CVE 的排名（0.999 = 比 99.9% 的 CVE 更危險）
- 若 API 無資料，回傳 `{"epss_score": None, "epss_percentile": None}`

### 測試重點
- `check_epss("CVE-2021-44228")` → `epss_score > 0.9`（Log4Shell 極高）
- `check_epss("CVE-9999-99999")` → `epss_score: None`
- API 連線失敗時拋出 `ConnectionError`

## 任務三：更新 LLM prompt（`kits/recommender.py`）

### 變更說明
當 `threat_intel` 存在時，將其注入 recommender 的 prompt，讓 LLM 基於數據給出有依據的優先級說明：

```python
threat_context = ""
if threat_intel:
    threat_context = f"""
威脅情報：
- EPSS 分數: {threat_intel.get('epss_score', 'N/A')}（被利用機率）
- EPSS 百分位: {threat_intel.get('epss_percentile', 'N/A')}
- 公開 PoC: {threat_intel.get('has_poc', 'N/A')}（數量: {threat_intel.get('poc_count', 'N/A')}）
- 已在野外被利用（CISA KEV）: {threat_intel.get('in_the_wild', 'N/A')}
"""
```

LLM 的 `priority` 與 `reasoning` 欄位應反映這些數據，而非只根據 CVSS。

### 測試重點
- 有 threat_intel 時，`recommendations.reasoning` 應提及 EPSS 或 PoC 數據
- 無 threat_intel 時，行為與原本一致
